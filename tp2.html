Passer d'une machine à un vrai cluster (1 master + 3 workers), puis calculer le chiffre d'affaires par ville avec MapReduce, en Java et en Python.

Sommaire

    Introduction

    Dans ce TP, l’objectif est de déployer un cluster Hadoop distribué de 4 nœuds composé d’un NameNode et de 3 DataNodes à l’aide de VirtualBox. Le cluster sera configuré avec HDFS pour le stockage distribué, YARN pour la gestion des ressources, puis validé par l’exécution d’un job MapReduce.

    Objectif du TP : installer un cluster Hadoop complet (1 master + 3 workers), configurer les communications réseau, activer HDFS et YARN, puis exécuter un traitement MapReduce permettant de calculer le chiffre d’affaires total par ville (en Java et en Python via Hadoop Streaming).

    1.4 Architecture de l’environnement

    Le cluster à déployer comporte 4 machines sur le réseau host-only 192.168.56.0/24 : le nœud master (192.168.56.10) héberge le NameNode et le ResourceManager ; chaque worker (datanode1 à datanode3) héberge un DataNode et un NodeManager. La carte NAT de chaque VM sert uniquement à l’accès Internet (téléchargements) et n’apparaît pas comme lien inter-machines.

    11.4 TotalSalesByCity.java

    À créer dans src/main/java/sn/isi/bigdata/TotalSalesByCity.java.

    package sn.isi.bigdata;

import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.Path;
import org.apache.hadoop.io.DoubleWritable;
import org.apache.hadoop.io.LongWritable;
import org.apache.hadoop.io.Text;
import org.apache.hadoop.mapreduce.Job;
import org.apache.hadoop.mapreduce.Mapper;
import org.apache.hadoop.mapreduce.Reducer;
import org.apache.hadoop.mapreduce.lib.input.FileInputFormat;
import org.apache.hadoop.mapreduce.lib.output.FileOutputFormat;

import java.io.IOException;

public class TotalSalesByCity {
    public static class SalesMapper extends Mapper<LongWritable, Text, Text, DoubleWritable> {
        private final Text city = new Text();
        private final DoubleWritable amount = new DoubleWritable();

        public void map(LongWritable key, Text value, Context context) throws IOException, InterruptedException {
            String line = value.toString().trim();
            if (line.isEmpty()) return;
            String[] fields = line.split("\t");
            if (fields.length >= 5) {
                try {
                    city.set(fields[2].trim());
                    amount.set(Double.parseDouble(fields[4].trim()));
                    context.write(city, amount);
                } catch (Exception e) {
                    System.err.println("Erreur parsing : " + line);
                }
            }
        }
    }

    public static class SalesReducer extends Reducer<Text, DoubleWritable, Text, DoubleWritable> {
        private final DoubleWritable total = new DoubleWritable();
        public void reduce(Text key, Iterable<DoubleWritable> values, Context context) throws IOException, InterruptedException {
            double sum = 0.0;
            for (DoubleWritable val : values) sum += val.get();
            total.set(sum);
            context.write(key, total);
        }
    }

    public static void main(String[] args) throws Exception {
        Configuration conf = new Configuration();
        Job job = Job.getInstance(conf, "Total CA par ville");
        job.setJarByClass(TotalSalesByCity.class);
        job.setMapperClass(SalesMapper.class);
        job.setReducerClass(SalesReducer.class);
        job.setOutputKeyClass(Text.class);
        job.setOutputValueClass(DoubleWritable.class);
        FileInputFormat.addInputPath(job, new Path(args[0]));
        FileOutputFormat.setOutputPath(job, new Path(args[1]));
        System.exit(job.waitForCompletion(true) ? 0 : 1);
    }
}

    11.6 Variante Python — Hadoop Streaming

    Hadoop Streaming permet d’écrire le mapper et le reducer en Python (ou tout autre langage lisant stdin / écrivant sur stdout). Créez les deux scripts suivants sur master avec nano.

    Prérequis : Python 3 doit être installé sur tous les nœuds (python3 --version). Rendez les scripts exécutables : chmod +x *.py.

    11.6.1 Mapper — total_sales_by_city_mapper.py

    #!/usr/bin/env python3
import sys

for line in sys.stdin:
    line = line.strip()
    if not line:
        continue
    fields = line.split("\t")
    if len(fields) >= 5:
        try:
            city = fields[2].strip()
            amount = float(fields[4].strip())
            print(f"{city}\t{amount}")
        except ValueError:
            continue

    11.6.2 Reducer — total_sales_by_city_reducer.py

    #!/usr/bin/env python3
import sys

current_city = None
current_total = 0.0

for line in sys.stdin:
    line = line.strip()
    if not line:
        continue
    parts = line.split("\t")
    if len(parts) < 2:
        continue
    city, amount_str = parts[0], parts[1]
    try:
        amount = float(amount_str)
    except ValueError:
        continue

    if current_city == city:
        current_total += amount
    else:
        if current_city is not None:
            print(f"{current_city}\t{current_total}")
        current_city = city
        current_total = amount

if current_city is not None:
    print(f"{current_city}\t{current_total}")

    11.7 Analyses complémentaires (même jeu de données)

    Après le job TotalSalesByCity (CA total par ville), vous réutilisez le même fichier purchases.txt en entrée HDFS. Chaque analyse consiste à adapter le couple clé / valeur émis par le mapper (et si besoin le type de la valeur) tout en conservant le principe d’agrégation par clé dans le reducer. Vous interprétez ensuite les sorties produites sur le cluster.

    Rappel sur les champs (séparateur tabulation \t) : date, heure, ville (index 2), catégorie (index 3), montant (index 4), moyen de paiement (index 5).

    Vous pouvez réaliser ces analyses en Java ou en Python (Hadoop Streaming). Les programmes sont à écrire vous-même, en partant du job « CA par ville » : identifiez ce qui change d’une analyse à l’autre (la clé, la valeur émise) et ce qui peut rester identique. Demandez-vous en particulier si le reducer du CA par ville peut être réutilisé tel quel.

    Entrée et sorties HDFS : gardez /input/purchases.txt comme entrée commune. Pour chaque nouveau job, utilisez un répertoire de sortie distinct (HDFS refuse d’écraser un dossier déjà existant), par exemple /output-ca-paiement, /output-ca-categorie, /output-nb-par-ville (ajoutez un suffixe -py pour les jobs Python). Supprimez ou choisissez un autre chemin si besoin : hdfs dfs -rm -r -f <chemin>.

    Analyse 1 — Chiffre d’affaires total par moyen de paiement

    Objectif : agréger le CA par type de carte ou paiement (Visa, MasterCard, Cash, Amex, Discover, etc.).

    Travail attendu : job MapReduce dans lequel le mapper émet la paire (moyen de paiement, montant) et le reducer additionne les montants pour chaque moyen de paiement (même logique que le CA par ville, autre clé). Exécution sur /input/purchases.txt.

    Livrables :

    • copie d’écran ou extrait texte de la sortie (hdfs dfs -cat sur un fichier part-r-* ou part-* du répertoire de sortie choisi) ;
    • une phrase d’interprétation : quel moyen de paiement concentre le plus de chiffre d’affaires sur cet extrait ?

    Analyse 2 — Chiffre d’affaires total par catégorie de produit

    Objectif : agréger le CA par catégorie (ex. Toys, DVDs, Men’s Clothing, …).

    Travail attendu : mapper qui émet (catégorie, montant) ; reducer par somme des montants par catégorie.

    Livrables :

    • sortie HDFS du job ;
    • identification des trois catégories les plus « rentables » sur l’extrait (d’après les totaux produits par Hadoop ou recalcul manuel pour vérification).

    Analyse 3 — Nombre de transactions par ville

    Objectif : compter combien de lignes (transactions) existent par ville. Sur le fichier du TP, une ville n’apparaît qu’une fois ; le pattern reste utile pour des jeux plus volumineux où une même ville se répète.

    Travail attendu : mapper qui émet (ville, 1) (valeur entière ou réelle « 1 » selon le type choisi) ; reducer qui somme ces valeurs par ville (la somme représente le nombre de transactions).

    Livrables :

    • sortie HDFS du job ;
    • court paragraphe comparant ce job au CA par ville : même clé « ville », mais mesure différente (comptage vs somme des montants) et conséquence sur la lecture des résultats.
